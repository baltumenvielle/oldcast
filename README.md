# OldCast

Stream PC games to an **Old Nintendo 3DS** at 30 fps, with sound, and play them with the
3DS buttons.

The Old 3DS (2011) has no hardware video decoder, and its 268 MHz ARM11 cannot decode
H.264 in real time, which is why Moonlight-based clients struggle on it. MPEG-2 is far
cheaper to decode: at 400x240 the Old 3DS decodes a gameplay frame in about 15 ms. This
project pairs a small MPEG-2 and ADPCM receiver for the 3DS with a PC side built on ffmpeg,
WASAPI audio capture and a virtual Xbox 360 controller.

**Status:** working on a local network. Measured on an Old 3DS over 2.4 GHz Wi-Fi during a
5-minute game session: 30 fps shown, 2 damaged frames, no lost audio or button packets.
Video takes 106 ms from the PC clock to the 3DS (measured automatically, 81 ms of it on the
PC), button packets make the round trip in under 10 ms, and audio plays about 50 ms after
it is captured. The 3DS finds the PC on its own, pairs with a PIN the first time, and the
PC has its own window, and the client installs as a CIA with its own HOME menu icon. It
also works from outside the home network (tested over a phone's mobile data), with every
message from the 3DS signed. Next step: a graphical interface on the 3DS. See [docs/design.md](docs/design.md) for the
measurements and the reasoning behind each choice.

## How it works

```
PC                                                   Old 3DS
screen ─ ddagrab ─ scale 400x240 ─ MPEG-2 2 Mbps ─┐
                                                   │ UDP 5004, MPEG-TS
                                                   └──► demux ─► libavcodec ─► Y2R ─► GPU ─► top screen
sound ─ WASAPI loopback ─ IMA ADPCM 48 kHz ───────┐
                                                   │ UDP 5006, 10 ms packets
                                                   └──► ADPCM decode ─► DSP (NDSP) ─► speakers
virtual Xbox 360 pad ◄─ host ◄──────── UDP 5007 ◄────── buttons, Circle Pad, touch (125 Hz)
```

- `client/`: the 3DS application (C, libctru, citro2d, libavcodec).
- `pc/oldcast/`: the PC host (Python): discovery and sessions, ffmpeg, audio, the virtual
  gamepad (ViGEm) and a local web interface shown in its own window.
- `pc/*.ps1`, `pc/tools/`: measurement scripts that drive the client directly.
- `docs/protocol.md`: discovery, pairing and session messages.

## Requirements

**3DS:** any model with custom firmware (Luma3DS) and the Homebrew Launcher. For sound,
`sdmc:/3ds/dspfirm.cdc` (dump it once with [DSP1](https://github.com/zoogie/DSP1)).

**PC (Windows):**
- [ffmpeg](https://ffmpeg.org/) 7.x on the `PATH` (uses `ddagrab`, Windows 8 or later).
- [ViGEmBus](https://github.com/nefarius/ViGEmBus) driver. Sunshine installs it too.
- Python 3.10 to 3.12 with the packages in `pc/requirements.txt` (the audio encoder uses
  the `audioop` module, removed in Python 3.13).
- To build the client: [devkitPro](https://devkitpro.org/wiki/Getting_Started) with the `3ds-dev` group.

## Build

From the devkitPro MSYS2 shell:

```bash
cd client
./scripts/build-ffmpeg.sh   # once: minimal libavcodec with the MPEG-2 decoder
./scripts/build.sh          # produces client/oldcast.3dsx
./scripts/build.sh cia      # also client/oldcast.cia, see below
```

The CIA (an installable title with a HOME menu icon and banner) needs
[makerom](https://github.com/3DSGuy/Project_CTR/releases) and
[bannertool](https://github.com/Epicpkmn11/bannertool/releases) in `client/tools/`. The
artwork in `client/assets/` is generated by `client/scripts/make-assets.ps1`.

PC side:

```bash
python -m venv pc/.venv
pc/.venv/Scripts/python.exe -m pip install -r pc/requirements.txt
```

## Play

1. On the PC, start the host: double-click `pc\OldCast.cmd` (or run
   `.venv\Scripts\python.exe -m oldcast` from the `pc` folder). Its window shows the
   connection, the settings and the paired consoles; closing it stops the host.
2. On the 3DS, install `oldcast.cia` with FBI and start OldCast from the HOME menu (or copy
   `oldcast.3dsx` to `/3ds/` and open it from the Homebrew Launcher). It lists the PCs
   running the host; choose one with **A**.
3. The first time, the 3DS shows a PIN and the PC window asks to allow it. Check that the
   PIN matches and click **Allow**.
4. Bring the game to the foreground on the streamed monitor and play. Hold **SELECT+START**
   for one second on the 3DS to stop.

### From outside your home

The host asks the router (UPnP) to forward UDP port 5007 to the PC; its window shows whether
that worked, and the option can be turned off there. If the router refuses, forward UDP 5007
to the PC by hand. Pair the 3DS at home once: it then keeps a key and the PC's public
address, and on any other network the PC appears in its list as "remote". Pairing is only
possible on the local network, and the PC ignores anything from outside that is not signed
with a paired console's key. This does not work if the internet provider of the PC uses
CGNAT (no public address of its own). The PC must stay awake with the host open.
Sessions from outside have their own highest video quality, set in the host window. They
start at 1 Mbps and the host adjusts the quality to what the connection carries, watching
the round trip the 3DS reports (see `docs/design.md`). They also survive up to 15 seconds
without contact, since Wi-Fi away from home can drop for a few seconds.

The host keeps a log in `%APPDATA%\OldCast\host.log`, including the requests it ignores and
why, which helps when a connection from outside fails.

`pc\play.ps1 -Ip <3ds-ip>` still works for development: it sends the client with `3dslink`
and pushes video and audio without a session (press **X** on the client's home screen to
listen).

### Controls

| 3DS | Xbox 360 |
| --- | --- |
| Circle Pad | left stick |
| touch screen | right stick (the point you touch is the center; small drags turn slowly) |
| A, B, X, Y | by position: bottom (B) is A, right (A) is B, left (Y) is X, top (X) is Y |
| L, R | LT, RT |
| D-pad, START | D-pad, START |
| SELECT (tap) | BACK |
| SELECT + L / R | LB / RB |
| SELECT + B / A | L3 / R3 |
| SELECT + START (1 s) | stop streaming |

The mapping lives in the tables at the top of [pc/gamepad.py](pc/gamepad.py).
`--radius` (default 90 pixels for full deflection) and `--curve` (default 1.8; 1 is linear)
tune the touch-stick sensitivity.

## Measure

- `pc\run-test.ps1 -Ip <3ds-ip> -Mode stream -Seconds 40` streams a test pattern and saves
  the client's per-second metrics to `results\`.
- `pc\run-test.ps1 -Ip <3ds-ip> -Mode bench` decodes `/3ds/oldcast/bench.ts` from the SD
  card without the network (create it with `pc\make-bench.ps1`), to check decoding speed alone.
- `pc\run-test.ps1 -Ip <3ds-ip> -Latency` measures end-to-end latency automatically: it shows
  `pc\latency-clock.html` full screen, and the 3DS reads the clock from the bars at the top of
  each frame. Add `-AB` to compare the client's two display configurations in one session.
- `pc\tools\pc_latency.py` measures the PC's share alone (capture, encoding, sending).

- `pc\run-test.ps1 ... -Audio` also streams the PC's sound during a stream test.

Metrics are also written to `/3ds/oldcast/metrics.csv` and shown on the bottom screen.
